Background worker, worktree `../thelastroom-w9`, branch `feat/42-retention` (from `main`

## Why

The owner wants players back on day 3 and day 5, and has "not received any notification".
Brief 26's rules made sure nobody testing could: phones only (none on the web), permission
after Mission 1, never the same day, and days 1, 2, 3, then 6.

## Done

- **Events first:** `test_reminder_sent` (`type`), `welcome_back_shown` (`days_away`,
  `target`), `welcome_back_closed` (`action`, `target`), in the enum and `docs/EVENTS.md`. Enum
  values only, no text.
- **The schedule (FR-51):** `planDays` is now **1, 3, 5, then 8** (was 1, 2, 3, 6), counted from
  the last time the game was open. A player who installs and plays on day 0 and doesn't come back
  hears from us on days 1, 3 and 5, then once more on day 8, then nothing until they open the
  game (which re-plans). The gaps only grow (1, 2, 2, 3): still at most one a day, 09:00–20:30
  (never after 21:00), backing off, and the off switch. Wordings rotate by position, so two in a
  row never repeat. Unit-tested (`reminder_plan_test.dart`).
- **"Send a test reminder"** (Settings → Reminders): on Android and iOS it plans as usual and
  shows the first reminder (tomorrow's) **now**, through the plugin's `show()`, with the same
  title, body and payload, so a tap deep-links like the real one (`/tower/mission/N` or
  `/tower/recall`). It works with the switch off and leaves it off. Without permission, the
  Mission 1 explainer comes first, then the system prompt; "Not now" sends nothing. On the web
  the button explains that reminders are phone-only.
- **The next reminder, visible:** a line under the switch: "Next: tomorrow at 19:40, from
  Priya" (or "from the Recall Room"), or why there's none: off, the phone blocking them (asked
  via `areNotificationsEnabled` / `checkPermissions`, so a permission revoked in the phone's
  settings shows), the web, or nothing left to remind about.
- **A re-plan keeps the shade:** `replace` cancels pending reminders only
  (`cancelAllPendingNotifications`), so the test reminder (or a delivered one) no longer vanishes
  the moment the app is hidden. ADR 0004 has an amendment.
- **Welcome back** (`features/tower/welcome_back.dart`, `welcome_back_card.dart`, one line plus
  an import in `tower_screen.dart`): after one or more calendar days away, the tower opens with
  a card in the next room's interviewer's voice ("WELCOME BACK · PRIYA", "Good to see you again.
  Here's what's waiting."): cards due, the next room, the week so far (the progress card's own
  non-judging line), and one quiet button to the first of them (the hero's amber "Play" stays
  the one primary). Dismissible (a drawn close mark, 44 pt), once per return (the visit is stored on the device;
  the card's state lives for the app's life), never on a first visit, never straight after a
  mission, never a count of days gone. Re-checked when the app comes back to the front. Built
  from `VividPanel`, `VividButton`, `Pressable` and the vivid type only, so brief 33's restyle
  (w7) carries it over.
- **The explainer scrolls** at 2x text on a small phone instead of overflowing (found by the new

- Docs: FR-51 and FR-53, README's reminders limit (with how to see one), ADR 0004 amendment,

## Decisions

- Days from the **last open**, not from install: any open re-plans (ADR 0004), so "day 3" is
  two days after the day-1 reminder if it was ignored. Anchoring to install would need a second
  clock and would keep nudging an active player on fixed days.
- Day 8 is past ADR 0004's "next 7 days"; one more pending notification is nowhere near iOS's 64.
- The welcome card's button is the quiet style: one amber action per screen (the hero's).
- The card's mission button goes straight to the mission (no lift ride), to keep the tower
  change to one line.
