## Decisions

- **Progress stays on the engine.** A voice attempt stores *which points were made* (from the AI
  or from the player's ticks) and the engine turns them into a `MissionScore`
  (`packages/engine/lib/src/voice_score.dart`), so a stored or restored voice attempt rescores
  offline exactly as before (ADR 0006's rule). The debrief shows the AI's four numbers and basis
  when it answered, like the Chapter 1 dossier.
- **Recording is PCM in memory.** `record`'s PCM16 stream (16 kHz mono) on every platform; the
  app computes the level itself and wraps the take as WAV. Continue appends to the same buffer,
  Delete empties it, nothing is written to disk, and the takes are dropped after the debrief.
- iOS needs CocoaPods now (`flutter_tts` has no Swift package): `ios/Podfile` and the two
  `#include?` lines in `ios/Flutter/*.xcconfig` came with `flutter pub add`.

## Half-done: the live run of `score-voice`

Done twice locally on the isolated stack with generated speech (`say` → `ffmpeg`, 17.3 s and
5.6 s), between 17:22 and 17:58 on 2 Nov. **Gemini never returned a verdict**: 503s, 120 s hangs,
then 429s (the key's rate limit). The text `score` function on the same key failed the same
way, and the network was fine (a keyless request reaches the Gemini host in 0.4 s), so it was the
key or Gemini, not this branch. Every failure was the designed code (502/504) with a clean log
line. To redo it:

```bash
# from a copy of supabase/ with its own project_id and ports, or the shared stack when free
supabase start && supabase functions serve score-voice --env-file ../thelastroom/.env
# sign in as an anonymous guest (POST /auth/v1/signup {}), then POST the request JSON (the
# fixture's points + two base64 WAVs) to /functions/v1/score-voice with the guest's JWT
```
