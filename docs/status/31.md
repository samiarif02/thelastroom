## Accessibility (done)

`test/a11y/audit_test.dart` boots every screen (tower, onboarding, title, file, report,
settings, Recall Room, practice CV, mission) and runs Flutter's `androidTapTargetGuideline` (48
dp), `iOSTapTargetGuideline` (44 pt), `labeledTapTargetGuideline` and `textContrastGuideline` in
all four themes, plus 2x text under reduced motion with no overflow. Found and fixed:

| Finding | Fix |
| --- | --- |
| Quiet buttons, gear, toggles at 44 dp (Android wants 48) | `BrandSpace.minTarget` 44 → 48; quiet `VividButton` and the gear follow it |
| Report header overflowed 63 px at 2x; Recall header 1.4 px | Back button squeezed the title to a letter a line. New `VividHeader` (button capped at 45%, title ≤ 2 lines) on file, report, Settings, Recall |
| Hero kicker 4.21:1 over the sunbeam | Sunbeam alpha 0.35 → 0.16 |
| CV labels and answer-card numeral: glow on a card's lit side, 4.18:1 in Sunset City | Soft white (≥ 5.2:1 everywhere) |
| Title's whole-frame tap unlabelled | `excludeFromSemantics` (Begin is the accessible way in) |
| Name field: second `textField: true` (web screen readers saw a disabled input; w2-c1) | Removed; the label merges into EditableText's own field |
| Onboarding cast said "Chapter 2/3" for interviewers met in Chapter 1 (w2-c1) | "First met in Mission N", from the content |
| Mission: 3 unlabelled taps in `mission_player.dart` | w2-c1 applies them in fix/30; the audit skips that one check until then |
| ChoiceCard numeral glow on deep (mission) | Sent to w2-c1 |

Leftover fixed: `/dev/sound` shows the audio section on a `VividPanel` (9a told).

## Performance

Measured on a `flutter build web --profile` bundle in headless Chrome (CDP, 412×915 @2x,
`requestAnimationFrame` intervals). Desktop Chrome on an M-series Mac, not the realme: relative
numbers, for before/after; the lead does the on-device check.

| Scenario | Before (avg / p95 / max ms, frames > 33 ms) | After |
| --- | --- | --- |
| Tower idle 5 s | 16.7 / 16.7 / 16.8, 0 | 16.7 / 16.8 / 16.8, 0 |
| Tower scroll (24 wheel steps) | 8.3 / 16.7 / 16.8, 0 | 8.3 / 16.7 / 16.8, 0 |
| First tap on the page (any tap) | max 183, 3 frames (183, 117, 67) | max 200, 3 frames |
| Theme switch ×3 (after the first tap) | 16.8 max, 0 | 16.8 max, 0 |
| Mission 1, first 12 s (card, dolly, lines) | 16.7 / 16.7 / 16.8, 0 | 16.7 / 16.7 / 16.8, 0 |

Findings:
- The one hitch is the **first pointer event on the page** (Flutter web's one-time input
  warm-up), whatever is tapped. The theme switch looked guilty only because it was the first tap;
  after any tap every switch is ≤ 16.8 ms. Not our code.
- **No rebuild storm:** a theme pick rebuilds each element once (about 620 element builds,
  `SettingsScreen` and the `TowerScreen` under it once each), in one frame
  (`test/perf/theme_rebuild_test.dart` guards it).
- **Continuous repaints on the tower: 4 breathing faces → 1.** The three 56 px chapter-card
  faces barely show their idle but each repainted every frame; they're still now
  (`InterviewerBadge.idle`), the hero's face still breathes. Desktop frames were already at the
  vsync floor, so this shows on the phone (GPU), not in these numbers.
