## How a second-device sign-in merges (`core/sync/account_merge.dart`)

1. The code is accepted; the client is now the account. Before the session switches,
   `prepareAccountMerge` (one local transaction): every attempt that already left the outbox was
   synced under this device's old guest id, and its `attempt_id` belongs to that guest's server
   row, so it gets a fresh id; every attempt is queued; the queued profile row is dropped;
   `account_merge = pending`. The Recall Room's ingested ids are carried over to the new ids.
2. The session switches → a new `SyncWorker` → `pullAccountMerge`: the account's attempts come
   down (insert or skip by `attempt_id`, like the restore); the account's profile wins when it
   has one, else this device's is queued up; the flag clears. Then the outbox sends this
   device's attempts to the account. Offline, the flag stays and every flush retries.
3. Result: the union of both devices' attempts on both; one profile (the account's). Left behind
   with the old guest: its server-side AI verdicts (`ai_scores`), which aren't merged.
