## NFR-3: method

NFR-3 is "60 fps on a mid-range Android". Budget: 16.6 ms per frame on each thread (UI build,
raster); a frame is dropped when either runs over.

1. **Widget level, every PR** (`test/perf/frame_budget_test.dart`): at rest, how many frames a
   screen still asks for and how many render objects repaint per frame
   (`debugOnProfilePaint`, `SchedulerBinding.hasScheduledFrame`). Catches the structural jank
   (a whole screen repainting for a small animation, tickers running for nothing) on any
   machine, deterministically.
2. **Device, by hand** (`integration_test/perf_test.dart`, profile build): the player's real
   flow on the device's own screen, with fakes only for storage, sound and analytics. Paths:
   `title` (first launch, 5 s), `tower_scroll` (4 flings), `door_to_room` (tap the play door →
   the room open), `mission_beat` (room 5's card, every line typing at its own pace, the cards,
   a line picked after reading), `why_step` (the reasons, one given, her reaction, the next
   cards), `debrief` (the reply locked → the Candidate assessment's slide, stamps, seal, pen),
   `your_file_scroll` (4 flings), `recall_room` (in, a note, an answer). Per path: the engine's
   `FrameTiming`s (what `watchPerformance` summarises; collected directly so they can sit inside
   `traceAction`, as both drive the VM timeline and can't nest) → frames, average / p90 / p99 /
   worst build and raster ms, frames over 16.6 ms on each thread and dropped
   (`reportData['summary']`); plus a `traceAction` timeline per path, which the driver turns into
   `build/perf/<path>_timeline.timeline_summary.json` (Flutter's own summary) beside the full
   timeline (open in DevTools or chrome://tracing). `build/perf/summary.json` holds the table.

## The device run (the lead runs it, when the phone is free)

The perf build is its own app: the Android `profile` build type has `applicationIdSuffix
".perf"`, so it installs as **com.thelastroom.app.perf** ("The Last Room (perf)") beside the
owner's **com.thelastroom.app** and never over it. Verified on the APK built here at this
branch: `aapt2 dump packagename` → `com.thelastroom.app.perf`, `aapt dump badging` →
`application-label:'The Last Room (perf)'`. Nothing was installed or run on the phone.

From the repo root, phone unlocked with the screen on (one guarded command: it stops before
`flutter drive` unless the APK's id is the perf one):

```bash
cd apps/mobile && \
flutter build apk --profile -t integration_test/perf_test.dart && \
APK=build/app/outputs/flutter-apk/app-profile.apk && \
ID=$(~/Library/Android/sdk/build-tools/36.1.0/aapt2 dump packagename "$APK") && \
if [ "$ID" = com.thelastroom.app.perf ]; then \
  flutter drive --profile --no-dds -d LFCQ8HKNAUDIFUPR --use-application-binary "$APK" \
    --driver test_driver/perf_driver.dart --target integration_test/perf_test.dart; \
else echo "STOP: $APK is '$ID', not com.thelastroom.app.perf"; fi
```

- Takes about 3 minutes on the phone (two tests: the title, then the session). The app plays
  itself on a fake, onboarded profile held in memory: nothing of the owner's is read or written.
- Results: `apps/mobile/build/perf/summary.json` (per path: frames, build/raster avg, p90, p99,
  worst, `missed_build`, `missed_raster`, `missed_frames` over 16.6 ms) and
  `build/perf/<path>_timeline.timeline_summary.json` (+ `.timeline.json`).
- Check before and after: `adb -s LFCQ8HKNAUDIFUPR shell pm list packages | grep thelastroom`
  lists both apps. Optional clean-up, the perf app only:
  `adb -s LFCQ8HKNAUDIFUPR uninstall com.thelastroom.app.perf`. Never uninstall or clear
  `com.thelastroom.app`.
