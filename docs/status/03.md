## Blocker for the lead (file I don't own)
- **Roboto is still fetched on the web.** The Flutter web engine downloads Roboto from
  fonts.gstatic.com at startup whenever the font manifest has no family named exactly `Roboto`
  (engine `canvaskit/fonts.dart`, `_robotoUrl`). Our fonts all load from the bundle; this one
  request is engine behaviour. Fix belongs in `apps/mobile/web/index.html` (not mine): pass
  `config: { fontFallbackBaseUrl: 'assets/fonts/fallback/' }` to `_flutter.loader.load`, so the
  engine never leaves the origin (it would 404 locally, harmless: every glyph we use is bundled).
  Alternatively brief 06 registers the chosen body font under the family name `Roboto` in
  `apps/mobile/pubspec.yaml`. CanvasKit itself also comes from gstatic in `flutter build web`
  (DESIGN.md must-do 2, `--no-web-resources-cdn`), also not mine.

## Second blocker for the lead: pre-push fails in every worktree
- `scripts/check-standards.test.mjs` "an empty directory fails every check" fails inside the
  pre-push hook when pushing from a worktree: git sets `GIT_DIR` for hooks, so
  `no-machine-local-state-tracked`'s `git ls-files` in the temp dir reads this repo and passes.
  Repro: `GIT_DIR=$(git rev-parse --git-dir) node --test scripts/check-standards.test.mjs`.
  Fix (scripts/ isn't mine): run the check's git calls with `GIT_DIR`/`GIT_WORK_TREE` removed
  from the env (or `cwd` + `--git-dir=<dir>/.git`). The owner approved `--no-verify` for this
  branch's pushes (2026-10-30), after every gate was run by hand.
