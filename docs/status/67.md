# Status 67: FR-3 by email link (no codes, no custom templates)

Worktree `../thelastroom-w32`, branch `feat/67-email-link-auth` from `origin/main` 0932216.
Never `supabase stop`, `db reset`, `supabase test db`, or any `supabase` command against the
hosted project.

## Why
#68 (status 60) built FR-3 with a 6-digit code, which needs custom email templates. The hosted
free-tier project can't edit templates without custom SMTP, and the owner doesn't want SMTP.
Supabase's default emails carry a confirmation link, so FR-3 now works by link (owner's choice).

## Progress log
- Read the rules, ADR 0008, status 60, the card, controller, backend and account merge.
- Read supabase_flutter 2.18.3 / gotrue 2.27.3: `detectSessionInUri` is on by default and runs
  `getSessionFromUrl` on every incoming app link with `code`/`error*` params (PKCE exchange);
  a failure reaches `onAuthStateChange` as a stream error (`notifyException`). `updateUser(email)`
  and `signInWithOtp` both send a PKCE code challenge.

## What was built
- `core/backend`: `sendLinkEmail` (`updateUser(email, emailRedirectTo: …/verified)`),
  `refreshAccount` (`refreshSession` then `getUser`), `sendSignInLink` (`signInWithOtp`,
  `shouldCreateUser: false`, `emailRedirectTo: thelastroom://auth-callback`), and the
  `accountLinks` stream. `verifyOTP` is gone (removed cleanly: the default emails carry no code,
  so a hidden code path could never be used). `AccountFailure.wrongCode` became `linkExpired`.
- Linked = `email` set, and either not anonymous or `email_confirmed_at` set with `new_email`
  empty (`SupabaseBackend.linkedEmail`; gotrue clears `is_anonymous` on the email-change verify).
- A sign-in link: supabase_flutter's `detectSessionInUri` (default on, PKCE default) exchanges the
  `?code=` and emits `signedIn`; the backend turns a `signedIn` for a non-anonymous user other
  than the one before into `AccountLinkSignedIn(session, previousUserId)`. An auth stream error
  that isn't an offline refresh or an expired session is `AccountLinkRefused` (the
  `#error=access_denied&error_code=otp_expired` redirect, or a PKCE code this device can't use).
- `SaveProgressController` listens from launch (`main.dart` keeps it alive), so a link that cold
  starts the app still runs #68's merge prep before the session switches. Link mode polls every
  5 s for 3 min and checks on every `AppLifecycleState.resumed`; "I've tapped it" checks at once.
  Resend waits a minute (the hosted project's email interval).
- Android: a VIEW intent filter for `thelastroom://auth-callback`, and `flutter_deeplinking_enabled`
  false (otherwise go_router would also get the link as a route). iOS: `CFBundleURLTypes`
  `thelastroom`, `FlutterDeepLinkingEnabled` false.
- `supabase/config.toml` (local): `site_url` and `additional_redirect_urls` as below;
  `enable_confirmations = true` kept; the code templates and their `[auth.email.template.*]`
  sections removed, so local sends the same default link emails as the hosted project.
- `web/src/app/verified`: "You're verified" (Priya smiling), "Open the app" (`thelastroom://`),
  the desktop line; an inline pre-paint script switches to "This link expired or was used" on
  `#error=…` and strips the code/token/error from the URL. Static, no JS framework needed.
- Tests: `save_progress_card_test.dart` (25), `supabase_backend_account_test.dart` (7). Stills in
  `.pr-screenshots/67/` (17 app + 3 web). No golden changed.
