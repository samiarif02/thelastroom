8x's scorecard (from the kit README §1 and §5):

| Criterion | Points | What earns it |
| --- | --- | --- |
| Claude logs | 15 | Own-words prompts, one goal per session, spec before code, pushback and corrections, logs committed with every PR. Pasted walls of text are flagged. |
| Architecture | 15 | 8x standards ported to Flutter, a pure tested engine, validated content, an idempotent offline outbox, tested RLS, no secrets in the app, ADRs. |
| Comms | 15 | Clear README, real PR descriptions, `docs/SUBMISSION.md`, narrated demo video, honest limits. |
| Initiative & thinking | 15 | Draft-first "then vs. now", the Recall Room, AI never grades accent, guest play, kind notifications, week-1 metrics, deliberate scope cuts. |
| Demos | 10 | Public web link (Mission 1 in 10 s), APK on a GitHub Release, 2–3 min video. |
| Shipping speed | 10 | Small, frequent PRs; Mission 1 early; web demo deployed early. |
| Design | 10 | The cinematic film language (brief §9); no Material defaults; goldens, a component catalog, every state designed. |
| Completeness | 10 | Chapter 1 end to end, offline/error/empty states, no dead buttons, CI green. |

**Why:** these are the only things that count; effort outside them is wasted.
**How to apply:** in every PR description and session, make the evidence for these visible.
